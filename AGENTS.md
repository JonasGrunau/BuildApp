# BuildApp

## Purpose
Psytrance buildup effect (VST3 / AU, JUCE 8). One chain: pitch (0..+12 st), low cut (left = off) and high cut (right = off) in FabFilter Volcano 3 style filters with a type menu and a resonance knob each (auto resonance on by default), white noise volume, pitch and low cut (200 Hz default), a one-knob buildup reverb, stereo narrowing (100 % default), level, dry/wet. Every knob at rest passes the signal bit for bit. Offline renders run the cuts oversampled. The editor shows the live input/output spectrum with the cuts' exact response and the noise band. Nineteen presets (`Presets.h`, sections Rise, Dark, Wash, Collapse, Progressive, Pumping Up, Downlift) lock the controls they use to a path along one BUILD knob (level and dry/wet always stay free). The path plays over BUILD 0..75 %; then the reverb comes up for a tail (to 80 %) and the level fades evenly in dB to -20 dB at 100 %, before the reverb. Most presets rest at BUILD 0 (bit-exact, BUILD back to 0 is the drop); Sunrise, Pumping Up, Downsweep and Freefall start at a setting of their own. Each timeline lane has an INTENSITY knob (`ba::Intensity`, 11 parameters, 0..100 %): how far the lane goes from where its control rests to the preset's path. EDIT opens the preset editor (a window of its own): every lane drawn and bent with Ableton Live's gestures and keys; the first change to a factory preset copies it into one of 16 user slots (PRESET's last choices), SAVE AS keeps it in the library (`~/Documents/BuildApp/Presets/*.bapreset`), and the project keeps every slot in use.

## For AI Agents

### Working In This Directory
- Core loop (seconds): `cmake -B build-core -G Ninja -DCMAKE_BUILD_TYPE=Release -DBUILDAPP_BUILD_PLUGIN=OFF && cmake --build build-core && ./build-core/buildapp_tests`
- Full plugin: `cmake -B build -G Ninja -DCMAKE_BUILD_TYPE=Release && cmake --build build` (installs into `~/Library/Audio/Plug-Ins`). A local JUCE: `-DFETCHCONTENT_SOURCE_DIR_JUCE=...`.
- Never include JUCE from `src/core`. New `.cpp` files go into `CMakeLists.txt` by hand.
- Audio thread: no allocation or locks in `processBlock` / `Buildup::process`. Buffers are sized in `prepare`.
- A stage's smoothers only advance while it runs: a silent stage snaps its targets (`setTargets`), so it wakes up where the knob is. Keep that when adding stages.
- At-rest exactness is tested (`Chain: every knob at its default passes the loop bit for bit`): a stage at rest must return early, not multiply by 1.
- Presets: a preset either rests at BUILD 0 (`restsAtZero`: bit-exact, tested at 3 rates, BUILD back to 0 is the drop) or starts at a setting on purpose (a closed lowpass, a downlifter's hit: no fade-in keys); a cut lane comes with its type; never drive level or mix. Lanes are in path terms (0..1 = BUILD 0..`kPathEnd`); the fade into the tail past it is global, not per preset. The preset index is the save format: append new presets at the end of `kPresets`. After changing one, run `buildapp_render` and keep it inside the `[level]` window (-6.5..+2.5 LU re the dry loop held at the path's quarters) with the noise under the music (`the noise stays under the music`: noise alone vs music alone, about -10 LU mid-build, -2..-3 at the top; hold loudness with the gain lane, not the noise). Presets never write parameters: the processor's `settings()` applies them to `ownSettings()`, so Off brings the user's knobs back. Intensities (`ba::Intensity`, one parameter per timeline lane, appended with version 5) go back to 100 % when the user picks another preset in the editor (`presetPicked`, via the menu's `beforeChoose`; Off and back to the same preset keeps them, the preset they belong to is saved in the state as `intensitiesOf`); automating PRESET never resets them, or it would fight their own automation; at all 100 % `applyPreset` must stay untouched (it returns before scaling), and at any intensity a preset that rests at BUILD 0 still does. A new lane needs a field in `Intensity`, a parameter, a `BuildTimeline::Lane`, a `ba::LaneId` (with its `laneKey`, the saved name) and an entry in the `kIntensities` test table.
- User presets: the audio thread only ever reads them through `PresetBank::forAudio` (one reader); the slots and the editor's working copy are the message thread's; `setStateInformation` runs there too (as `replaceState` wants). Every edit plays at once (`UserPresets::set` publishes), so the chain's own smoothers keep live edits click-free (`[bank][click]`). Never let an edit leave a lane untidy: go through `ba::edit` (or `edit::assign`). The PRESET choice list is factory then user slots: appending a factory preset is fine (the `factoryCount` remap), but never move the user slots.
- JUCE 8 API: text widths via `theme::textWidth`; numbers via `fmt::` (`src/plugin/Format.h`), never `juce::String (x, 0)`.

### Testing Requirements
- After core changes: `./build-core/buildapp_tests` must pass (presets at rest, lane shape, loudness window, noise under the music, distinct paths, the fade into the tail, the drop back to bit-exact, progressive and pumping-up shapes, intensity: towards rest, one lane each, rest at any intensity, `[click]` no jumps while turning; halfband rejection, filter response vs computed for every type, slopes, auto resonance ranges, click-free switching (`[click]`: type changes mid-crossfade, an HQ cut waking, pitch waking with its work spread over the blocks), HQ aliasing, pitch intervals, tone residual, chord artifacts and kick timing, noise level and low cut, reverb RT60 and drop, reset and repeatable renders, bit-exact rest, all rates).
- New cut types: add to `Characters.h`, then check the bump along the sweep stays under +14 dB (the auto-resonance test) and that `Cut filters: every type sweeps the loop bounded` passes.
- After UI changes: build `buildapp_snapshot`, render `<dir>` (and `<dir> --scale=1`) and read the PNGs; `steps` shows the menus' `<` `>` keys hovered, held and dimmed; `switched` prints the intensities after Off, back, and the next preset (expect them kept, kept, all 100 %); `pressed` holds EDIT down (its bottom edge must stay); `lanes` renders section A alone for every factory preset; `edit*` render the preset editor (a key's value box, a fork, Draw Mode, a selection's handles, mid-bend, empty, smallest size, the SHORTCUTS panel, every lane scrolled with a segment hovered, a breakpoint the keys added and raised, zoomed into a selection). After preset editor or user preset changes: `buildapp_snapshot <dir> selftest` must print no FAIL (fork, undo/redo, the state round trip playing bit for bit the same, the library, the factory-count remap, the lane keys: Enter adds, Esc takes back without an undo step, Enter Up Enter is one undo step; zoom: Z, X, a pinch, the adaptive grid, a swipe, Cmd-wheel).
- Lane editing: `./build-core/buildapp_tests "[edit],[text],[bank]"` (inserts and cuts exact on bent segments, pass-over, snaps, bends through the mouse, draw steps / freehand, ranges, handles, shapes, simplify, a random-edit fuzz; every factory preset round-trips through text; torn reads never; a live edit glides).
- Before a release: `auval -v aufx BdAp Jgru` and pluginval at strictness 5 on both formats.

### Common Patterns
- Namespaces: `ba` (core), `ba::dsp` (primitives), `ba::map` (knob meanings), `theme` (UI tokens and helpers), `fmt` (number text). Plugin/UI classes are global.
- JUCE-style formatting: space before call parens `foo (x)`, 4-space indent, braces on their own line.
- Look ("night sheet", PhaseFucker's sibling): sheet `#131211`, bone ink `#ECE7DB`, one acid accent `#C8F03C` only for what builds tension (cut curve, build-knob rings); no gradients, shadows or glow; corner radius 2 px; IBM Plex Sans Condensed labels, IBM Plex Mono numbers.
